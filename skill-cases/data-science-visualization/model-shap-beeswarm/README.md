# model-shap-beeswarm

## 典型图型与场景

- 图型：`shapBeeswarmPlot`，模型局部解释的分布。
- 覆盖：密集区域的纵向蜂群堆叠、逐样本贡献、特征内色标、复合唯一键、缺失特征值。

## 数据验收

- 共 720 条记录、240 个样本、3 个特征，各特征 240 个点；唯一键是 (id,feature)，不能按 id 全表去重。
- 三个特征均含不同样本的重复或相近贡献，必须保留原值与重复权重，不采样、去重或人工改变 x 值。桌面宽度下应出现真实纵向堆叠；只把 240 点全叠在一条水平线上不通过。
- 特征顺序为近30天逾期次数、负债收入比、账户月龄。横轴为 shapValue，不得混用 featureValue 或 abs(shapValue)。
- S012/近30天逾期次数：SHAP=3.2、特征值=5；S001/账户月龄：SHAP=0.55、特征值=6；S012/账户月龄：SHAP=-0.55、特征值=72。
- S004/负债收入比：SHAP=0、featureValue=null，应保留点并使用缺失灰色，不能丢弃或补零。负债收入比共 8 个 featureValue=null，另 7 个为 S013、S050、S087、S124、S161、S198、S235；每个 SHAP 值均有效。其他真实 featureValue=0 的点不是缺失。
- 单位为 log-odds，正负表示相对基准的输出贡献方向，不能写成概率增加百分之几、因果效应或真实模型能力证据。

## 实际操作验收

1. 悬停上述正、负、零/缺失贡献点，核对 ID、特征及两个不同含义的数值。
2. 检查颜色来自特征值且按各特征内部范围表达；高账户月龄对应负 SHAP 也必须正确着色。
3. 在桌面宽度下检查 3 行蜂群的密集区有明显纵向排布；读取真实图元可用时，核对每行 240 点及多个 y 位置，不能只核对静态截图。允许库报告实际拥挤，但不能通过采样或丢弃点消除警告。
4. 在密集区的上缘、下缘各定位一个不同样本，核对 Tooltip 的 ID/特征/贡献/原始值确实不同；再核对上述边界检查点。色标可读，没有聚合成三个均值点或重要性条形图。
