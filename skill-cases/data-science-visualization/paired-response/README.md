# paired-response

## 典型图型与场景

- 图型：`pairedComparisonPlot`，同一对象的前后变化。
- 覆盖：真实 ID 配对、固定阶段顺序、不完整配对。

## 数据验收

- 共 25 条观测，13 个不同 ID；12 个完整配对，设备 013 只有升级前 230 ms 的单点。
- 12 个完整配对中，响应时间下降 9 个、上升 2 个、不变 1 个。不能把下降数量当作因果证据。
- 001 应连接 120→100 ms，005 为 160→165 ms，003 为 110→110 ms；ID 的前导零保留。
- 应有 12 条按 ID 对应的连接（其中一条数值不变）及全部 25 个阶段观测；禁止按输入顺序连接或补齐 013 的升级后值。

## 实际操作验收

1. 悬停 001 的两个端点、005 的升级后端点和 013 单点，核对 ID、阶段与毫秒值。
2. 检查横轴阶段顺序与连线对应关系；单点不应接到其他设备。
3. 不应出现自动显著性检验、因果结论或页面筛选。

## 执行与公共验收

按[执行说明](../README.md#执行方式)只复制 [prompt.md](prompt.md) 和 [inputs/](inputs/) 给 Agent；本文件及 [fixtures.json](fixtures.json) 留在验收端。输入来源与 SHA-256 见校验清单。

同时检查[公共验收标准](../README.md#公共验收标准)。允许不同的配色和布局，不要求页面或像素一致。数据事实用于检查产物，不强制把所有计算写在页面上。

本目录提供固定任务定义，不代表已经完成 Agent 执行或人工视觉验收。
