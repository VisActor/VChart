# spec 生成

用于用户需要完整 VChart 配置、机器消费的 JSON，或已有宿主负责渲染的场景。复用 [共享生成流程](scenario-2-generation.md)，不要求用户提供 JS/React 技术栈。

## 目标与已知约束

使用表达目标、真实数据、已知图型及已有上下文。只检查会影响当前产物的宿主约束：版本、支持图型、尺寸、JSON/JS、回调和外部资源。未知不代表完全支持或完全禁止，不为填满检查表逐项追问。

上下文已说明宿主接收配置时，后续“用合适图表展示”继续交付 spec。新增样式、切换图型、修复报错不改变交付目标；只有用户明确要求 HTML、组件或其他产物时才转换。

## 完整配置与增量修改

交付包含实际数据或明确可用数据绑定、图型必需字段和用户要求配置的完整 spec。柱图常用 xField/yField，饼图常用 categoryField/valueField，不能给所有图型套用统一字段清单。

修改已有 spec 时保留未请求变更的部分并返回整合后的完整配置。只有用户明确要求“只给改动”“补丁”“片段”时才返回增量；“加标签”本身不代表要求补丁。

配置不包含 HTML、实例创建、render 调用、外部事件绑定、飞书卡片外壳或传输代码。宿主适配由调用方负责，不能把特定宿主的包装当作 VChart spec。

## JSON 与 JS

选择顺序：用户要求 → 已知宿主契约 → 已有配置格式。均未指定时，可序列化配置采用 JSON；实际需要且环境允许函数时采用 JS spec，并说明格式要求。

- JSON：只使用 JSON 值。用标准解析器检查，不含注释、函数、undefined、NaN/Infinity。数据中的 0、null、Unicode 和顺序保留。
- JS：保留文档化回调与其签名，不经 JSON 序列化往返。可交付 `const spec = {...};` 配置声明，但不附应用实例代码。
- `formatter` 模板字符串和 `formatMethod` 函数按 [标签类型](../references/type-details/ILabelSpec-Type-Definition.md) 区分；先查询声明式能力，不把所有格式化需求判成函数。
- 纯 JSON 宿主不能携带实例事件、任意回调或业务副作用。无法声明式实现时说明限制与宿主所需能力；不删除函数后声称完成，也不擅自转为 HTML。

完整 JSON 和回调示例见 [示例说明](../examples/spec-generation/README.md)。示例数据只供参考，不能替代真实任务数据。

## 交互边界

tooltip、图例、标签及其他支持的声明式交互可包含在 spec 内。外部按钮、点击发业务请求、实例更新等属于应用 API，不混入纯配置。用户需要 spec 加应用接入说明时分别交付；只要 JSON 时不能混入这些说明。

## 验证

根据可用环境完成并区分：

1. 数据/配置检查：字段实际存在，数据绑定可用，类型和必要配置正确；单位、顺序、缺失、零和分母未被静默改变。
2. 格式检查：JSON 使用标准解析器；JS 对照函数签名并检查实际代码。本期不采用 schema 校验。
3. 真实渲染：可用时用交付的同一份配置验证数据图元与效果。临时 JS 声明可以包装 JSON，临时 HTML 可复用既有演示工具；它们只用于验证，不取代 spec 产物。

数据引用需要宿主提供时，在可用的实际绑定环境验收；环境缺失则说明限制，不填 mock 数据伪装成功。浏览器验证记录其实际环境，不能据此声称飞书或其他宿主验证通过。

发现字段或配置问题直接修正并重检。没有浏览器时仍可交付完成自检的配置，明确未执行渲染，不将解析成功写成渲染通过。

## 交付

机器消费的“只返回 JSON”只返回配置本身，不加 Markdown 围栏、说明、自定义检查字段或实例代码。普通对话可交付 `.json`/`.js` 文件和简短说明，验证证据与配置分开。

同时要求 HTML 预览时交付配置与使用它的页面。后续调整两者使用同一配置，不维护两份不同数据或字段映射。
