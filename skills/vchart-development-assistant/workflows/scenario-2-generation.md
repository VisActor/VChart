# 配置生成：共享流程

用户从零生成图表、修改已有 spec 或询问配置写法时使用。完整生成与增量修改是既有模式，与 HTML/spec 交付目标分别判断。

## 确定交付

使用 [主文件的选择规则](../SKILL.md#先确定任务与交付目标)，再只读取所需专项流程：

- [HTML 生成](scenario-2-html-generation.md)：直接打开查看、可运行 demo；没有宿主上下文的独立展示默认此路径。
- [spec 生成](scenario-2-spec-generation.md)：配置写法、完整 spec、JSON 或已知消费配置的宿主。
- 同时需要两者时，在生成同一份配置后分别交付；已有 React 组件需求沿用 [React 专项](scenario-1-react.md)。

后续修改、诊断与还原保留当前交付目标。HTML 内的 spec 是修改输入，不重新触发 spec 交付；显式改变输出要求时按主文件规则切换。增量修改默认交付整合后的完整产物，只有明确要求片段或补丁才仅给改动。

## 理解目标与数据

检查会影响图义的字段含义、单位、顺序、缺失和分母；不要把数字 ID 当作连续度量。使用真实数据，不默认抽样、聚合、截断或补零。功能教学可以采用明确标注的 mock 数据。

数据和目标充分时直接选择图型，不逐次询问确认。只有缺失信息改变图义或交付可用性时才澄清。

## 选图与定位配置

完整生成参考 [图型指南](../references/chart/chart-type-guide.md)，根据表达目标和数据含义选择；用户已指定图型时优先尊重要求，数据不能支持时说明原因。

增量修改以现有配置为基础，保留未请求改变的数据、组件、函数和宿主约束。按需查询：

| 意图 | 配置入口 |
| --- | --- |
| 显示数值、加标签 | `label` |
| 参考线或基准线 | `markLine` |
| 累加、堆叠 | `stack` |
| 多系列对比 | `seriesField`；按图型配置分组或堆叠 |
| 图例、悬浮提示、轴标题 | `legends`、`tooltip`、`axes[].title` |

从 `../references/topkey/[图型].json` 或 `all_common.json` 定位配置；再查询对应 type-meta 和必要的 type-details，不凭近似属性名构造配置。

生成或修改 Sankey 时，先读取 [Sankey 专项示例](../references/examples/sankey/basic-sankey.md)，确认 `data` 数据源描述与 `values` 图数组的层次，再选择适用形式。

生成或修改 Treemap 时，先读取 [Treemap 专项](../references/chart/treemap.md)，确认布局节点的原始记录取值与默认图例。

已知图型或遇到空数据、图/树结构、回调问题时，按 [数据结构排查](../references/chart/common-issues.md#图数据与层级数据) 读取相关参考。

## 生成和检查

1. 根据实际图型配置数据、字段映射和必需属性。VChart 支持的数据对象/数组写法均可，不机械套用唯一数据结构。
2. 对复杂属性或函数按需查类型签名；例如标签回调用 `formatMethod`，`formatter` 是模板字符串能力，不能混用。
3. 声明式交互直接写 spec；实例 API 只在用户需要应用代码时追加，遵循主文件的交互边界。
4. 检查字段是否存在、数据是否保留、配置是否符合已知版本/宿主要求；发现问题直接修正。
5. 进入所选交付流程。能渲染时检查实际数据和图元，不能时如实说明；JSON 解析不能代替渲染检查，本期不使用 schema。
