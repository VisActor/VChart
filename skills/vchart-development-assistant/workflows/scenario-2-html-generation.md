# HTML 生成

用于独立展示、可打开查看的 HTML 和可运行 demo。复用 [共享生成流程](scenario-2-generation.md) 的配置，不重新定义选图规则。

## 输入与产物

表达目标与数据充分时直接生成。独立页面默认原生 JS，不机械追问框架；已有 React 上下文按 [专项流程](scenario-1-react.md) 交付组件代码，明确要可运行页面时再提供 React 诊断 HTML。

最终 HTML 包含依赖引用、完整 spec、容器和标准实例创建。外部按钮、点击处理、导出等应用逻辑只按需求添加；模板本身的编辑演示保留，不能仅给 spec 后声称已交付 HTML。

## 使用既有生成器

先保存实际生成的配置为 JS 文件，格式为 `const spec = {...};`。只包含配置声明，不在该输入文件里放 `new VChart`、render 或事件绑定，因为演示模板负责实例创建。

脚本的模板路径相对工作目录；从实际技能目录运行：

```sh
cd /实际技能目录
python3 scripts/generate_demo_html.py \
  --title "周数据比较" \
  --desc "比较四天的实际数值" \
  --feature "展示周一至周四的数值" \
  --tips "可编辑配置调整图表" \
  --spec-file /实际输出目录/spec.js \
  --output /实际输出目录/chart.html
```

参数见 [脚本参考](../references/SCRIPT_PARAMS_REFERENCE.md)。生成器用于配置演示，不会把输入文件里的外部事件代码自动绑定到模板创建的实例；应用 API 需求应基于生成页面和其真实实例按文档接入，不另建第二个图表。

脚本无法使用时可按 `../template/demo.html` 生成完整页面。正确替换占位符并检查依赖；不是只返回被截断的 HTML 片段。

## 按需交互

图例、tooltip 和标签等声明式能力直接使用 spec。点击读取 datum、外部状态联动、实例数据更新等参考主文件的 API 导航，接到实际实例。

仅请求 spec 的任务不能因交互而自动转为 HTML；两类产物同时请求时，页面使用所交付的同一份 spec，应用事件代码单独存在于页面。

## 验收与交付

实际打开生成页面，检查：

- 用户数据、字段、单位和顺序一致；有真实数据图元，不只看文件或 canvas 是否存在。
- 可见效果对应表达目标；回调标签、tooltip 等内容正确。
- 有明确交互需求时，执行真实动作并检查 datum、筛选结果或状态变化，不能只记录“点击成功”。
- 记录实际运行环境与版本证据。CDN 或浏览器不可用时说明未完成的渲染验收，不把生成成功写成图表验证通过。

给出完整 HTML 文件链接及必要用途说明。用户同时要 spec 时附配置产物；只需要 HTML 时无需再强制交付一组额外文件。诊断或图片还原沿用专项解释要求。
